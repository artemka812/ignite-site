# Развёртывание

Локальный сайт запускается через `manage.py runserver`. Публикация требует отдельного выбора хостинга и подтверждения владельца; изменения проекта автоматически в интернет не отправляются.

Для размещения нужен Python 3.12+, PostgreSQL, WSGI-сервер (например Gunicorn на Linux) и HTTPS через обратный прокси или средствами платформы. Точка входа — `config.wsgi:application`. Development-сервер не использовать как публичный сервер.

Настроить окружение на хостинге:

- `DJANGO_DEBUG=0`;
- постоянный случайный `DJANGO_SECRET_KEY`, хранящийся в секретах хостинга;
- `DJANGO_ALLOWED_HOSTS` — домены через запятую;
- `DJANGO_CSRF_TRUSTED_ORIGINS` — полные HTTPS-адреса;
- `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` — выделенная база;
- `DJANGO_BEHIND_PROXY=1` только при доверенном прокси, который сам перезаписывает X-Forwarded-Proto.

После установки зависимостей выполнить `manage.py migrate`, `manage.py collectstatic --noinput`, `manage.py check --deploy`. Статику из `staticfiles/` обслуживает прокси или платформа. При DEBUG=0 включены HTTPS-перенаправление, secure cookies и HSTS. До включения HSTS домен должен действительно работать через HTTPS.

Проверить вход, создание команды и турнира, генерацию сетки, результат матча и плееры на реальном домене. Twitch получает текущий домен в параметре parent. Некоторым видео YouTube владелец запрещает встраивание — для них предусмотрена ссылка.

Настроить регулярные резервные копии PostgreSQL и проверить восстановление в отдельной базе. Не переносить локальные секреты, `work/`, `.venv/` и тестовую базу в публичный репозиторий. Нагрузку в 100 пользователей и совместимость всех браузеров нужно проверять отдельно на выбранном хостинге.
