# Роли и регламент турниров

## Пять ролей по ТЗ

| Роль | Планируемые действия |
| --- | --- |
| Гость | Смотреть опубликованные турниры, команды, сетки и расписание без входа. |
| Игрок | Всё, что доступно гостю; вести свой профиль, подавать заявку на вступление в команду, видеть свои матчи. |
| Капитан | Управлять своей командой и составом, регистрировать команду в турнире. |
| Организатор | Управлять своими турнирами, принимать заявки, задавать пары, расписание, счёт и ссылки на эфиры. |
| Администратор | Управлять пользователями, доступом и всеми данными сайта. |

Сейчас публичная часть работает на чтение, а запись — через стандартную административную панель Django. Публичная регистрация, личные кабинеты и действия капитана/организатора реализуются на следующих неделях. Их страницы доступны только как отключённые макеты в `/previews/`.

В `User.role` хранятся `player` и `organizer`. Капитан определяется ссылкой `Team.captain`; у гостя нет аккаунта. Для административной панели нужны `is_active`, `is_staff` и разрешения Django; полный доступ получает `is_superuser`. Поле `role=organizer` само по себе не даёт доступа в админку. Администратор создаётся отдельной командой, открытой регистрации с выбором привилегий нет.

## Подготовка турнира через админку

1. Создать пользователей игроков. Если вход им пока не нужен, оставить пароль неиспользуемым.
2. Создать команды и назначить капитанов. В составе команды добавить игроков со статусом «Участник».
3. Создать турнир: уникальный адрес, дисциплина, формат, сроки, лимит и правила. Черновик не показывается гостям.
4. Создать заявки команд и принять участников. Номер посева начинается с 1 и не повторяется среди принятых.
5. Внести матчи вручную: раунд, порядковый номер, команды, время и формат встречи.
6. Поставить турниру статус «Скоро» или «Идёт турнир». Проверить его публичную страницу.

`seed_demo` создаёт этот пример автоматически для удобства первого запуска. Команда повторно не перезаписывает существующие значения и не удаляет данные. Все 21 учебный аккаунт имеют неиспользуемые пароли, администратор в эти примеры не входит.

## Олимпийская система

Команда выбывает после поражения. Победители полуфиналов играют в финале. В примере четыре команды: два полуфинала и финал. При числе команд, не равном степени двойки, в будущем алгоритме будут предусмотрены проходы без игры. На этапе 30.10 автоматическая генерация и продвижение ещё не реализованы: пары и ссылки на следующий матч задаются вручную.

Все учебные встречи — BO3, то есть до двух побед по картам. Итоговые счета: 2:0, 2:1, 0:2, 1:2. Ничья в завершённом матче недопустима. При вводе завершённого счёта нужно также изменить статус матча на «Завершён».

## Круговая система

Каждая команда встречается с каждой один раз. Для `n` команд получается `n × (n - 1) / 2` матчей. Например, для четырёх команд — шесть. При нечётном числе команд одна команда пропускает тур; это не поражение.

Для учебного проекта принимаются правила: 3 очка за победу, 0 за поражение. Ничьи в BO3 отсутствуют. При равенстве очков сравниваются разница побед и поражений по картам, затем число выигранных карт, затем личная встреча. Если равенство сохраняется или образуется круговое равенство нескольких команд, организатор назначает дополнительный матч. Автоматический календарь и расчёт таблицы появятся на этапе логики турниров.

## Проверка результата второй пятницы

Изменить в админке название турнира, время одного матча и ник игрока. Обновить главную и страницу турнира — должны появиться новые значения. Остановить и снова запустить Django: изменения должны сохраниться. Дополнительная проверка: создать новый пустой турнир со статусом «Скоро» и увидеть понятные сообщения об отсутствии матчей и участников.
