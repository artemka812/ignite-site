# IGNITE

Учебный сайт для сопровождения киберспортивных турниров.
Команда П-24-68Б: Чефранов, Восковец, Карелов.

## Версия к 30 октября 2026

Существующий дизайн первой демоверсии сохранён. Данные теперь хранятся в PostgreSQL и редактируются через административную панель Django.

- Главная: турнир и матч из базы, фактические количества турниров, команд и дисциплин.
- Список турниров: поиск, фильтры по дисциплине и статусу, актуальные карточки.
- Страница турнира: описание, правила, принятые команды, составы, вручную заданная сетка по раундам и расписание.
- Пользовательская модель с уникальным email для входа и игровым профилем.
- Восемь сущностей из ТЗ, их связи, миграции и проверки данных.
- Админка `/admin/`: пользователи, команды, составы, турниры, заявки, матчи, трансляции, история счёта.
- При изменении счёта через админку автоматически создаётся запись истории с автором.
- `/previews/`: отключённые макеты регистрации, входа, профиля игрока, команды и кабинета организатора.
- Понятные состояния пустых турниров, списков участников и матчей.

Турниры и результаты учебные. Открытой регистрации, редактирования через личные кабинеты, автоматической генерации сеток, продвижения победителей и встроенных плееров пока нет: это следующие этапы плана.

## Технологии

Python 3.12–3.14, Django 5.2 LTS, PostgreSQL 14 или новее, psycopg 3, HTML и обычный CSS. Отдельная сборка фронтенда, Bootstrap и Node.js для запуска не нужны.

## Первый запуск в Windows

Открыть PowerShell в папке проекта. На этом компьютере `.venv` уже создано; если его нет, сначала выполнить `py -3.12 -m venv .venv` (для другой поддерживаемой версии заменить номер).

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe configure_postgres.py
```

Мастер просит хост, порт, имя администратора PostgreSQL и его пароль скрытым вводом. Создаёт **новые** базы `ignite_site` и `test_ignite_site`, отдельную роль `ignite_site_app` и локальный `config.local.ini`. Роль приложения не получает прав суперпользователя и создания других баз. Если одноимённые объекты или файл настроек уже существуют, мастер останавливается и ничего не перезаписывает. После успешной настройки повторять мастер не нужно.

Пароль `postgres` не сохраняется. Случайный пароль отдельной роли приложения и постоянный секрет Django хранятся в исключённом из Git `config.local.ini`. Не отправлять этот файл, скриншоты его содержимого и реальные пароли в чат или репозиторий.

Если база уже настроена вручную, использовать `config.local.ini.example` как образец или переменные `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DJANGO_SECRET_KEY`. Переменные окружения имеют приоритет.

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

При `createsuperuser` указать email, ник и собственный пароль. Мастер демонстрационных данных администратора не создаёт, общих паролей в коде нет.

Открыть [сайт](http://127.0.0.1:8000/), [админку](http://127.0.0.1:8000/admin/) или [макеты](http://127.0.0.1:8000/previews/). В админку входить по email, не по нику. Сервер останавливается `Ctrl+C`.

## Повторный запуск

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Данные PostgreSQL сохраняются при перезапуске Django. Пустую базу сайт показывает корректно; `seed_demo` необязателен и нужен только для учебных примеров.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test --keepdb --noinput
```

Тесты используют **отдельную** базу `test_ignite_site`, заранее созданную мастером, а не базу сайта. `--keepdb` позволяет роли приложения работать с готовой тестовой базой без права создавать/удалять базы. Не задавать `DB_NAME=test_ignite_site` для обычного запуска приложения и не хранить реальные данные в тестовой базе.

Для автономной проверки без PostgreSQL есть явный тестовый режим с временной SQLite в памяти:

```powershell
.\.venv\Scripts\python.exe manage.py test --settings=config.test_settings
```

Это только тестовая настройка. Основной сайт автоматически на SQLite не переключается.

Ручная проверка: изменить название турнира, время матча и ник игрока в админке, обновить публичные страницы, перезапустить сервер и убедиться, что значения остались. Нулевой счёт должен отображаться как `0`, а отсутствие счёта — как `—`. Черновики гостям не показываются.

## Структура

```text
config/                       настройки Django, PostgreSQL и маршруты
configure_postgres.py         интерактивная локальная настройка новой базы
config.local.ini.example      безопасный образец настроек
config.local.ini              локальные секреты, в Git не попадает
tournaments/models.py         восемь сущностей и проверки
tournaments/admin.py          административная панель
tournaments/views.py          чтение базы и подготовка данных страниц
tournaments/management/       команда seed_demo
tournaments/migrations/       схема базы для развёртывания
tournaments/data.py           исходные примеры только для seed_demo
tournaments/tests.py          проверки страниц, моделей и админки
templates/                    страницы сайта и макеты
static/css/site.css           оформление и адаптивность
docs/database.md              схема базы и ограничения
docs/roles-and-rules.md        таблица прав и регламент турниров
```

Настройки предназначены для локальной разработки. Перед публикацией отдельно настраиваются хостинг, разрешённые домены, HTTPS и отключение `DJANGO_DEBUG`.
